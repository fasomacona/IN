¿Qué es la Inteligencia de Negocios?

La Inteligencia de Negocios (Business Intelligence o BI) es el proceso de integración y tratamiento de los datos para convertirlos en información que permita apoyar a los tomadores de decisiones en la organización.

Definición clave: La BI se compone de todas las actividades relacionadas con la organización, entrega y análisis de información. Incluye Minería de Datos, Administración del Conocimiento, Aplicaciones Analíticas, Sistemas de Reportes y principalmente Data Warehousing.

Esta asignatura aporta al perfil del Ingeniero en Informática la capacidad de comprender desde la extracción de datos de sistemas existentes hasta la explotación de la información mediante herramientas de análisis. Permite el descubrimiento de conocimiento en las bases de datos de una empresa y la creación de almacenes de datos (Data Warehouse) hasta la utilización de herramientas de minería de datos para el soporte en la toma de decisiones.

Objetivo del Tema 1

Proporcionar una visión integral de la importancia de la Inteligencia de Negocios en el entorno actual y cómo utilizarla como herramienta estratégica para alcanzar los objetivos de la organización.

Competencia específica del tema:
Identificar los conceptos básicos, herramientas y componentes de la Inteligencia de Negocios.

1.1 Conceptos Básicos

1.1.1 Data Warehouse (Almacén de Datos)

Un Data Warehouse es una colección de datos orientada a un tema, integrada, variable en el tiempo y no volátil, que se utiliza para apoyar el proceso de toma de decisiones gerenciales.

Fue definido formalmente por Bill Inmon (considerado el padre del Data Warehouse). A diferencia de las bases de datos operacionales (OLTP), un Data Warehouse está diseñado para el análisis histórico y la generación de reportes estratégicos.

1 Orientado a temas

Los datos se organizan alrededor de temas principales del negocio (clientes, productos, ventas, finanzas) en lugar de aplicaciones operativas.

2 Integrado

Los datos provienen de múltiples fuentes heterogéneas y se unifican bajo un mismo formato, nomenclatura y codificación.

3 Variable en el tiempo

Mantiene el historial de los datos a lo largo del tiempo (años), permitiendo análisis de tendencias y comparaciones históricas.

4 No volátil

Los datos una vez cargados no se modifican ni eliminan. Solo se realizan operaciones de lectura (consultas) y carga periódica.

Arquitectura general de un Data Warehouse

Fuentes de Datos (OLTP, ERP, CRM, Archivos planos, Sistemas legados)
↓
Procesos ETL (Extracción · Transformación · Carga)
↓
Data Warehouse / Data Marts
↓
Motor OLAP · Minería de Datos · Consultas ad-hoc
↓
Reportes · Dashboards · Tableros de Control · KPIs

1.1.2 Data Mart

Un Data Mart es un subconjunto de un Data Warehouse orientado a un área específica del negocio o a un departamento particular (ventas, marketing, finanzas, recursos humanos, etc.).

Característica Data Warehouse Data Mart
Alcance Toda la organización Un departamento o área específica
Tamaño Grande (terabytes o más) Más pequeño y manejable
Tiempo de implementación Meses o años Semanas o pocos meses
Enfoque Corporativo / Estratégico Departamental / Táctico
Costo Alto Moderado
Tipos de Data Mart:
  • Dependiente: Se crea a partir de un Data Warehouse corporativo ya existente.
  • Independiente: Se construye directamente desde las fuentes operacionales (sin DW previo).
  • Híbrido: Combina datos del DW corporativo con datos locales del departamento.

1.1.3 Tipos de Sistemas de Información

En el contexto de Inteligencia de Negocios es fundamental distinguir entre los sistemas operacionales y los sistemas de soporte a la decisión:

OLTP Sistemas Transaccionales

On-Line Transaction Processing

  • Procesan transacciones del día a día
  • Alta frecuencia de inserción/actualización
  • Datos actuales y detallados
  • Optimizados para escritura
  • Ejemplos: ERP, CRM, sistemas de punto de venta

OLAP Sistemas Analíticos

On-Line Analytical Processing

  • Orientados al análisis y consulta
  • Principalmente operaciones de lectura
  • Datos históricos y agregados
  • Optimizados para consultas complejas
  • Ejemplos: Data Warehouse, cubos multidimensionales

Comparación OLTP vs OLAP

Aspecto OLTP OLAP
Propósito Operaciones diarias Análisis y toma de decisiones
Modelo de datos Relacional (normalizado) Multidimensional (estrella/copo de nieve)
Consultas Simples y predefinidas Complejas y ad-hoc
Usuarios Cientos o miles de usuarios concurrentes Analistas y gerentes (pocos)
Actualización Continua (en tiempo real) Periódica (batch)

1.1.4 Variables de Medición

Las variables de medición (también llamadas hechos o métricas) son los valores numéricos que se desean analizar. Representan el “qué” se quiere medir.

  • Monto de ventas
  • Cantidad de unidades vendidas
  • Costo de producción
  • Número de clientes atendidos
  • Tiempo de entrega
  • Margen de utilidad

1.1.5 Variables de Análisis

Las variables de análisis (también llamadas dimensiones) son los ejes o perspectivas desde las cuales se analizan las métricas. Representan el “por qué”, “dónde”, “cuándo” o “quién”.

  • Tiempo: Año, trimestre, mes, día
  • Geografía: País, región, ciudad, sucursal
  • Producto: Categoría, línea, marca, SKU
  • Cliente: Segmento, tipo, zona
  • Empleado / Vendedor
  • Canal de venta
Ejemplo práctico:
“¿Cuánto se vendió (variable de medición) de la categoría Electrónica (dimensión Producto) en la región Norte (dimensión Geografía) durante el segundo trimestre de 2025 (dimensión Tiempo)?”

1.2 Componentes de la Inteligencia de Negocios

La Inteligencia de Negocios no es una sola tecnología, sino un conjunto de componentes que trabajan de forma integrada. A continuación se describen los principales:

1.2.1 Minería de Datos (Data Mining)

Es el proceso no trivial de identificar patrones válidos, novedosos, potencialmente útiles y, en última instancia, comprensibles a partir de los datos.

Utiliza herramientas de software orientadas a descubrir relaciones ocultas que el usuario no necesariamente sabe que está buscando. Separa grandes volúmenes de datos e identifica relaciones entre ellos.

Cinco tipos de información que proporciona la Minería de Datos:

1. Asociación

Ocurrencias ligadas a un evento.
Ejemplo: Cuando se compra atún, también se compra mayonesa.

2. Secuencia

Eventos ligados a lo largo del tiempo.
Ejemplo: Si se compra una casa, el 45% de las veces se compra una cocina dentro de un mes.

3. Clasificación

Encontrar características de los clientes para determinar qué tipos de promociones serán más eficientes.

4. Agrupamiento (Clustering)

Descubrir diferentes agrupamientos de datos. Útil para detectar defectos en fabricación o segmentar clientes.

5. Previsión (Predicción)

Estimar comportamientos futuros.
Ejemplo: Probabilidad de que un cliente renueve su contrato.

1.2.2 Administración del Conocimiento (Knowledge Management)

Es el proceso de capturar, distribuir y utilizar de manera efectiva el conocimiento de la organización. En el contexto de BI, convierte los datos y la información en conocimiento accionable que puede ser compartido y reutilizado.

  • Captura del conocimiento explícito e implícito
  • Almacenamiento en repositorios estructurados
  • Distribución a través de portales y sistemas de colaboración
  • Aplicación en la toma de decisiones estratégicas

1.2.3 Aplicaciones Analíticas

Son sistemas especializados que utilizan los datos del Data Warehouse o Data Marts para realizar análisis avanzados orientados a áreas específicas del negocio:

  • Análisis de rentabilidad de clientes
  • Análisis de canasta de mercado (Market Basket Analysis)
  • Predicción de demanda
  • Detección de fraude
  • Análisis de riesgo crediticio
  • Optimización de inventarios

1.2.4 Sistemas de Reportes

Permiten generar y distribuir reportes estáticos o dinámicos a partir de los datos almacenados. Incluyen:

  • Reportes operativos diarios / semanales
  • Reportes ejecutivos resumidos
  • Reportes ad-hoc definidos por el usuario
  • Suscripciones y envío automático por correo

1.2.5 Multidimensionalidad

Es el enfoque de modelado de datos que organiza la información en cubos multidimensionales (hipercubos), donde las medidas (hechos) se analizan a través de múltiples dimensiones.

Operaciones analíticas básicas de los sistemas OLAP:
  • Slice: Seleccionar una “rebanada” del cubo (fijar una dimensión)
  • Dice: Seleccionar un subcubo (fijar varios valores de dimensiones)
  • Drill-down: Bajar al detalle (de año → mes → día)
  • Roll-up: Subir al resumen (de día → mes → año)
  • Pivot (Rotación): Cambiar la orientación de las dimensiones

Ejemplo de pregunta que un sistema OLAP responde:
“¿Por qué las ventas de automóviles de un determinado modelo disminuyeron en el segundo trimestre?”

1.2.6 Data Warehouse (como componente central)

El Data Warehouse es el componente central de la arquitectura de BI. Actúa como el repositorio único de la verdad (Single Source of Truth) que alimenta todos los demás componentes: minería de datos, reportes, dashboards, OLAP y aplicaciones analíticas.

1.3 Principales Herramientas de la Inteligencia de Negocios

Existen múltiples herramientas comerciales y de código abierto para implementar soluciones de BI. El programa oficial menciona especialmente las siguientes:

Oracle

Oracle Database + Oracle Analytics Cloud + Oracle Data Integrator. Solución robusta empresarial.

IBM DB2

DB2 + IBM Cognos Analytics. Fuerte en entornos mainframe y análisis avanzado.

Microsoft SQL Server

SQL Server + Analysis Services (SSAS) + Reporting Services (SSRS) + Integration Services (SSIS) + Power BI.

Power BI

Herramienta moderna de Microsoft para visualización, dashboards interactivos y self-service BI.

Tableau

Líder en visualización de datos. Excelente para exploración visual y storytelling con datos.

SAP BusinessObjects

Suite completa de BI orientada a grandes corporativos.

Qlik Sense / QlikView

Motor asociativo que permite explorar relaciones entre datos de forma libre.

Pentaho / JasperSoft

Opciones de código abierto (open source) para BI y reportes.

Nota importante: Aunque el programa menciona “Wired for OLAP”, actualmente las herramientas más utilizadas en la industria y en entornos académicos son Power BI, Tableau, SQL Server Analysis Services y soluciones en la nube (Azure Synapse, Google BigQuery, Amazon Redshift + QuickSight).

Propiedades deseables de una solución de BI

  • Amplitud: Capacidad de integrar datos de múltiples fuentes
  • Profundidad: Nivel de detalle histórico disponible
  • Calidad de los datos: Exactitud, completitud y consistencia
  • Almacenamiento inteligente y escalable
  • Análisis avanzado (predictivo, prescriptivo)
  • Facilidad de uso para usuarios de negocio (self-service)

Resumen del Tema 1

Al finalizar este tema el estudiante debe ser capaz de:

  • Definir qué es la Inteligencia de Negocios y su importancia estratégica
  • Diferenciar Data Warehouse de Data Mart
  • Distinguir sistemas OLTP de sistemas OLAP
  • Identificar variables de medición y variables de análisis
  • Explicar los principales componentes de una solución de BI
  • Reconocer las herramientas más utilizadas en el mercado
  • Comprender el flujo general: Fuentes → ETL → Almacén → Análisis → Presentación
